# Camera Demo

Учебный C++17 проект. Сейчас: mock-видео → заглушка обработки → CSV метаданных.
Аппаратное декодирование и кодирование — следующий этап.

## Сборка и запуск

Требуются CMake 3.20+, компилятор C++17, OpenCV (модуль core), pkg-config
и development-пакеты FFmpeg: libavformat, libavcodec, libavutil.
FFmpeg подключён к сборке. Утилита `video_info` открывает файл и находит
видеопоток через его API; чтение кадров ещё не реализовано.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/camera_demo build/mock_frames.csv
```

Для существующего видеофайла: `./build/video_info path/to/video.mp4`.
Вывод: индекс видеопотока, codec, размеры и time base. Ошибка открытия или
отсутствие видеопотока завершают программу с кодом 1. GPU здесь не используется.

## Три объекта в main

- `Video` читает кадры. Единственный интерфейс; `createMockVideo()` скрывает
  конкретный класс и возвращает `unique_ptr<Video>` — владельца видеовхода.
  Будущая реализация спрячет захват и decoder внутри себя.
- `Processor::process(Frame&)` пока ничего не меняет.
- `Writer` сохраняет метаданные в CSV. Отдельный объект позволяет независимо
  выбирать источник и место записи; encoder позже будет внутри writer.

`Frame` содержит только `image` (`cv::Mat`, сейчас CPU) и `timestamp`
(микросекунды от начала видео). Mock выдаёт пять изображений 4×2 с шагом 40 мс.
`read()` возвращает `optional<Frame>`: кадр либо EOF; ошибки — исключения.
Кадр сохраняет владение своей памятью после следующего чтения.

`Writer::finish()` явно закрывает файл, чтобы обнаружить ошибки записи.
Путь можно передать первым аргументом; родительский каталог должен существовать.
CSV не содержит изображения и не является видеофайлом.

## Развитие

В `include/camera/` — объявления, в `src/core/` — реализации, в `apps/` — main,
в `tests/` — проверки. Временные файлы — в `tmp/`, сборка — в `build/`.
`tools/video_info.cpp` — маленький диагностический пример открытия через libavformat;
это промежуточный шаг перед реализацией настоящего `Video`.

Работа последовательная. GPU-кадры, таймауты, отмена и потоки появятся с реальными
задачами. При подключении hardware backend представление `image` потребуется
расширить для GPU-памяти; текущий CPU mock не задаёт обязательное копирование с GPU.
